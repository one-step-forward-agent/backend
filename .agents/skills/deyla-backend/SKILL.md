# Изменить бэкенд Deyla

Работай из корня Backend. Найди обработчик по пути запроса с учётом префикса роутера и проверь подключение в `app/main.py`. Публичные модели ищи в `app/schemas.py`, `app/analytics_schemas.py` и в самом модуле маршрута. Найди существующий тест по URL или имени домена, чтобы установить текущие поля ответа, коды ошибок и права вызывающей стороны.

- **Пользовательский запрос.** В `app/api/deps.py` зависимость `get_current_user` читает Bearer-токен или cookie, задаёт язык и контекст учёта LLM. Для объектов с общим доступом проверь разрешения на конкретную операцию в профильном сервисе.
- **Запрос бота.** Проверь контракт `app/api/internal.py` и привязку Telegram к пользователю. Фикстура `user` в `tests/conftest.py` даёт пару из пользовательских заголовков и chat_id, а `BOT_HEADERS` содержит заголовок внутреннего API.
- **Ассистент и внешние сервисы.** Для изменения обработки сообщения проследи вызовы из `app/services/chat.py` и `app/services/agent.py`; адаптер модели находится в `services/gigachat.py`. В тестах ответ модели можно задать через `fake_gigachat`. Для календарной интеграции начни с `app/services/integrations/registry.py` и конкретного провайдера.
- **Хранение.** Сопоставь изменения модели в `app/models/models.py` с миграцией в `alembic/versions`. Найди текущую вершину командой `python -m alembic heads`. При смене типа, обязательности или шифрования поля проверь чтение существующих записей после миграции.

Для календарной арифметики можно выполнить `python -m pytest tests/test_dates.py -q` без базы данных. Для интеграционных сценариев подготовь отдельный PostgreSQL по `tests/README.md`, явно задай его DATABASE_URL перед `python -m alembic upgrade head` и запусти pytest для изменённого домена. Например, поведение inbox проверяет `tests/test_proactivity.py`, передачу задач — `tests/test_reassignments.py`, подтверждение отправки — `tests/test_send_drafts.py`.
